# Stage 007 · 放大实际图形，按空间排版讲解

2026-10-31。用户反馈：图示偏小、留白过多；右侧不应一句一页，应尽量完整展示，只在确实放不下时分页，并维持单屏无滚动。

## 问题与设计

- Stage 006 图形仍沿用 680×340 的空白坐标画布，矩阵也套在固定宽度容器中；缩放的是外框而非实际图形。
- 讲解按固定 40/80 字及固定表格行数分页，桌面有足够空间时也拆成多页。
- 本轮保留实验台外部尺寸与播放控制，改变内容适配：课程图形计算节点、标签、字幕及弯曲边权的边界；矩阵测量真实表格宽高。AI 综合专题保持专用图示布局。
- 右侧使用相同排版样式的不可交互测量节点，根据当前字体、换行、段落间距、表格行高、侧栏宽高计算页面。先尝试整节同页放下，只有溢出才预留翻页控件。多个段落和表格尽量同页；过长段落/表格按实际剩余高度拆分，保留内容顺序。
- ResizeObserver 与字体加载事件触发重新排版；页数减少时修正当前页，重复选择同一说明栏目返回第一页。默认“这一步”同时包含当前变化、原因、边界与下一步提示，让大屏可以充分利用讲解空间。
- Huffman 最终帧不再重复展示只剩一棵树的候选森林，腾出空间显示编码树；原文仍保留。

## 实现与验证发现

- 初次调整发现 motion.svg 的动态 CSS 宽高未随 viewBox 同步更新；改为由普通 DOM 容器管理实时尺寸，SVG 占满该容器，继续保留连线/节点动画。
- 修正分页器对表格溢出时需仅添加当前页可容纳的行，并在下一页继续剩余行。文本使用 Unicode 字符边界分割，不丢弃输入字符；测量内容用 textContent 插入，测量区 aria-hidden + inert，不进入阅读顺序。
- Browser plugin not available，沿用 Playwright + 本机 Chrome；截图查看 1366×768 桌面与实际 viewport 390×664 手机模拟。额外通过窗口变更检查 1366×600、1366×900、390×844。
- 针对性用例检查：默认 Huffman 桌面结果整页显示全部五行码表、编码和解码校验；节点显示尺寸阈值；图形使用一条可用边的至少 94%；窗口变小时页数增加，变大时合并；逐页核对所有五行码字与编码位串；单屏控制命中、全屏进出和无内部滚动继续保留。
- 全目录首/中/末帧增加节点外壳、字幕与边权标签未被裁切检查。

## 验证与发布

本地 290 项单元/性质测试、TypeScript 与生产构建通过；最终 30 项桌面/手机浏览器用例全部通过，含 79 课全部 A/B 场景首中末帧的节点与边权边界检查。最终桌面和手机截图已查看：Huffman 图形明显放大，桌面结果与完整码表同页显示。独立 CI 与发布信息待推送后追加。

边界：单节点/小图放大有上限，避免占据整屏；极窄视口下大图仍需缩小，点击元素可查看数值。手机尺寸为模拟视口，未做真机验收。
